# VA-MEM-003 — The guardian and the extension must agree on `pressure.json`

**ID:** VA-MEM-003
**Checked:** 2026-11-14 19:05 UTC
**Level:** 1, unit, real write path with synthetic sensors; fixture consumed by the Node suite.

## Failure prevented

`~/.local/state/strata/pressure.json` is the only channel between the memory guardian and the voice extension. Every deferral decision the extension makes reads this file. If the guardian ever renames or drops a field, `readMemoryPressure` treats the file as "no data": `shedVoice` defaults to false and `headroomGiB` to `MAX_SAFE_INTEGER`, so speech proceeds straight into a machine the guardian is trying to protect — silently, with no error anywhere.

## Reproduction (before the fix)

A probe fed the real extension code a payload generated by the guardian's actual `write_pressure` with two mutations (`headroomGiB` → `headroom_gib`, `shedVoice` → `shed_voice`):

```
parsed: { shedVoice: false, headroomGiB: 9007199254740991 } isMemoryTight: false
```

At 61.4 GiB system used — above the guardian's 61 GiB shed line — the extension reported no pressure. Nothing failed; the deferral simply stopped existing.

The gap was structural: `tests/test_memory_guardian_policy.py` stubs `write_pressure` (line 137: `mod.write_pressure = lambda snap, shed: pressures.append(shed)`), so no test had ever executed the real publish path, and no artifact pinned the schema the extension parses.

## Change

- `tests/fixtures/guardian-pressure.json`: the payload produced by the guardian's verbatim `write_pressure` at 61.4 GiB (`{"at": "2026-11-14T18:57:04Z", "systemUsedGiB": 61.4, "headroomGiB": 2.6, "pressureLevel": 4, "freePercent": 25, "shedVoice": true, "llmBusy": true}`), atomic tmp-write + `os.replace` exercised for real.
- `tests/test_memory_guardian_contract.py` (3 tests): the exact key set and types (`at` matching the ISO-Z regex the extension's `Date.parse` accepts); the shed/headroom boundary is consistent — whenever `headroomGiB < 3.0` (the extension's deferral bound) the `shedVoice` flag is also set at every trace from 60.0 to 62.0 GiB, so the extension's "shedVoice or headroom < 3" rule can never be half-satisfied by rounding; and a drift alarm asserting the committed fixture's fields equal what the installed guardian writes.
- `tests/memory-pressure.test.ts`: one new test parses the fixture through the real `readMemoryPressure`/`isMemoryTight` (re-stamping `at` so the 30 s staleness rule does not false-trigger), plus an explicit assertion that the mutated rename shape parses as no-pressure data — the documented fail-safe, since the guardian's kill logic remains the backstop.

The extension and the guardian thresholds themselves were not modified.

## Result

PASS. `pytest tests/test_memory_guardian_contract.py tests/test_memory_guardian_policy.py -q` → 15 passed. Node `memory-pressure.test.ts` + `voicebox-refusal.test.ts` → 24 passed. Full suites: 250 Python, 88 Node.

## Limitations

- Sensors are synthetic; the contract is about the file format, not the machine's real memory state.
- The drift alarm compares against the guardian installed on this Mac; CI on Linux skips it (skipif). A guardian change on a machine without the tests re-run would still ship drift unnoticed until the next local run.
- End-to-end: deferral against a live guardian writing to the live file with a live VoiceBox remains unverified while port 17493 has no listener.
