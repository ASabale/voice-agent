# VA-PLAY-002 — Dead-session playback slots are pruned

1. **ID:** VA-PLAY-002
2. **Name:** The playback state directory does not accumulate forever
3. **Objective:** A playback slot whose session process is gone is removed on read, so long-lived installations do not grow unbounded and never re-read dead sessions.
4. **Failure investigated:** On 2026-11-14 `~/.local/state/omp-voice/tts-playing/` held nine slot files (10 to 19 hours old) whose session pids were all dead. Nothing in the controller or the extension unlinked them; every mic frame re-read all of them.
5. **Preconditions:** Repository checkout, the project virtualenv.
6. **Required application versions:** None.
7. **Required services:** None. Do not start or stop the controller.
8. **Hardware requirements:** None.
9. **Setup:** From the repository root. Tests use temporary directories.
10. **Execution:**
    ```sh
    ~/.local/share/omp-voice/venv/bin/python -m pytest tests/test_playback_state.py -q
    ~/.local/share/omp-voice/venv/bin/python scripts/run_stale_session_probe.py
    ```
11. **Fixtures:** Slot files with stubbed `pid_alive`. No audio in the unit leg. The live leg starts an isolated `omp` session that speaks real VoiceBox audio through the real speakers; the probe opens no microphone and signals no protected pid.
12. **Expected behavior:** `_read_playback_slots` unlinks a slot when its session pid is dead and the slot is not currently speaking (past the 0.6 s reverb tail, or its `afplay`/writer pids are dead). A slot inside the reverb tail is kept and still counts as speaking. A live session pid is never pruned. When the controller prunes any slot, it re-derives the flat `tts-playing.json` projection from the surviving slots, because a session SIGKILLed mid-clip would otherwise freeze the projection at `playing: true` forever — which would make the memory guardian skip voice shedding permanently. The Node extension's `readSlots` prunes symmetrically (dead session pid, not speaking) before publishing the aggregate.
13. **Pass/fail:** Unit: assertions pass. Live: after SIGKILLing a speaking session mid-clip, the orphan `afplay` keeps the render reference connected while it is still running (echo is real), then the session's slot is unlinked, `tts-playing.json` re-derives to `playing: false`, `status.json` reports `render_connected: false` and state `IDLE`, no wake line fires on the uncancelled echo, and the controller survives.
14. **Metrics:** File existence after read; projection JSON contents after prune; kill-to-prune latency; kill-to-render-drop latency.
15. **Evidence:** `tests/test_playback_state.py` 25 passed (2026-11-14 19:19 UTC, incl. `test_project_aggregate_never_freezes_without_a_live_witness`); full suite 254 passed (also 254 in a clean Python 3.12 CI venv after the VA-CI-001 model fix); Node `tests/playback-state.test.ts` 19 passed incl. `projectAggregate requires a live afplay or writer witness`; full Node suite 89 passed. Earlier runs (2026-11-14 11:52 UTC): 24 + 77 with the first three projection tests. The nine live stale files disappeared during the earlier iteration from a source the loop did not observe (controller pid 64238 runs HEAD code with no pruning and logs no removal); the pruning behavior itself was proven only by unit tests until 23:41 UTC. Live leg (2026-11-14 23:41 UTC, `.local/voice-agent/runs/VA-PLAY-002-LIVE.json`): probe session pid 92640 spoke a 10.4 s clip through the real speakers; SIGKILL 2 s in left the orphan `afplay` running 7.75 s more. Throughout the orphan period the live controller (pid 38298) kept `render_connected: true` and suppressed wake (zero wake lines). At afplay exit the slot was unlinked in the same poll tick (7.75 s after kill), `tts-playing.json` re-derived to `playing: false` at the same instant, `render_connected` went false within 1 s (reverb tail), log line `render reference unavailable` at 18:40:58 local, controller alive, state IDLE, `mic_dropped: 0`, `mic_invalid: 0`. New unit test `test_an_orphaned_afplay_is_kept_then_pruned_when_it_exits` pins the same shape.
16. **Known failure modes:** Pruning happens only on read. If no controller read and no session publish occurs after a crash, the stale projection survives until the next read — the guardian's own afplay-pid liveness check (VA-MEM-004, 2026-11-14 19:20 UTC) is now the backstop for that frozen state. Before 2026-11-14 19:19 UTC the projection itself trusted the bare `playing` flag: a writer-lease slot whose writer died before `afplay` ever spawned projected `playing: true` with **no pid at all**, so the guardian had no witness to check and deferred voice shedding conservatively and forever. `project_aggregate` (Python, and `projectAggregate` in the extension) now takes a `pid_alive_fn`/`alive` predicate and derives `playing` with the same rule `slot_is_speaking` uses; callers that already liveness-check their slots (legacy tests with stub pids) keep the flag-only path by omitting the predicate. EPERM from `process.kill(pid, 0)` is treated as alive (conservative). Fixture probes must claim their slot under a live pid (`os.getpid()`); a synthetic dead pid gets its slot pruned mid-run — this actually happened: `run_double_talk_probe.py` crashed with `FileNotFoundError` on 2026-11-14 11:17 UTC.
17. **Cleanup:** Tests delete their temporary directories.
18. **Automation status:** LEVEL 1 unit + LEVEL 3 live probe (real session, real speaker output, real controller; no microphone opened by the probe).
19. **Known limitations:** Prune on read is now demonstrated live on controller 38298. Two boundaries remain: (a) the sessions/ bridge registry is pruned lazily too — `load_session_registry` unlinks dead-pid entries only when a wake/delivery read runs, so entries for dead sessions can linger (11 files present at 23:40 UTC) until the next read; the read always prunes before use, so a stale port is never delivered to. (b) An orphan afplay whose session died is trusted until its clip ends: `orphan_lease_expiry` uses the reference clip's real-time duration (`frames / sample_rate / playback_rate`) plus 5 s spawn slack; slots without a reference still fall back to the flat 60 s cap. The 120 s clip cases are proven by unit vectors, not by a physical >60 s orphan clip — VoiceBox sentence chunks observed so far are 4.1–15.1 s, so the long-clip path is exercised only in the contract vectors.
